Wants and offers

A want is something still open between you and someone: they need something from you. An offer is something they put out. Both use the Murmurations offers and wants shape.

Built 2026-10-09. The field names below come from the published Murmurations offers and wants schema. Five more are ours. The people and items are made up to show the shape.

What each field holds

From the published Murmurations offers and wants schema, version 0.1.0. Required there: linked_schemas, exchange_type, transaction_type, tags, title, description, geographic_scope, contact_details.

linked_schemas
The formats this file follows: offers_wants_schema-v0.1.0.
exchange_type
offer or want. An offer is something to lend, lease, sell or donate. A want is something to borrow, rent, buy or receive.
item_type
good, something made, or service, something performed.
transaction_type
On what basis: borrow-lend, rent-lease, buy-sell, receive-donate. A list; more than one is allowed.
title
A few words saying what it is.
description
One to three sentences. For a want opened from a note, the note's context goes here.
tags
Words to find it by.
details_url
A web page with more about it. For a shared link, the link.
image
An image address for it.
geographic_scope
Where it is available or wanted: local, regional, national, international.
geolocation
Where it is, as lat and lon.
contact_details
How to reach whoever offers or wants it: an email, a contact_form address, or both.
expires_at
When it expires, as a Unix timestamp: seconds since 1970, a number.

Five fields are ours, because the Murmurations schema has none for them. Required: id, whose, status.

id
ow_ and 10 hex characters. The same want filed twice gets the same id.
whose
Whose want or offer it is: a person (per_), an organization (org_), or a project (prj_) for your own want.
opened_by
The exchange that opened it, by its exc_ id, when one did.
status
open until it is met, then done. A done want stays on file.
closed_at
When it was marked done.

What the file looks like inside

JSON, a plain text format. This is Kai's want: the Murmurations fields, plus ours. It is stored as one file, offers-wants/<id>.json. It points at Kai by whose and at the exchange by opened_by.

  "id": "ow_9d4e2b71c0",
  "linked_schemas": ["offers_wants_schema-v0.1.0", "contacts_offer_want_addon-v0.1.0"],
  "whose": "per_kai-tran",
  "opened_by": "exc_3f9a1c0b2d",
  "status": "open",
  "exchange_type": "want",
  "item_type": "service",
  "transaction_type": ["receive-donate"],
  "title": "Look at the tool list for the library",
  "description": "Kai sent the tool list for the library and asked for a look before it goes out.",
  "tags": ["tools", "library"],
  "details_url": "https://example.org/tool-list",

  "expires_at": 1793491200,

How it connects

Your own want works the same way: one record on a project, with the people who might meet it pointing at it, each saying how they relate. A note's with list does this: each person or organization named gets a connection, can-meet for a want or offered-to for an offer, pointing at the ow_ id.

How a note opens and closes one

opens
On an exchange in the note. Opens a want. Whose it is: the other party. The exchange is what opened it.
wants, offers
Lists in the note, for ones no exchange opened. Each says whose, and can say with.
done
A list of ids, for example ["ow_9d4e2b71c0"]. Each is marked done with the time. Nothing is removed.
