Community Legibility Spec

A specification for ending data extraction and exploitation: the hardware and protocols needed to move data between individuals without a platform in between, and the minimum data communities need to broadcast for discoverability.

More about the 3 horizons

Data Sovereignty Infrastructure

Your work stays on your machine. What travels is its shape: when it happened, and the principle it stands on. That is enough for a community to match people without anyone holding everyone’s data.

Local Legibility Packet

A vault-agnostic, installable system that turns markdown folders into shareable HTML artifacts.

Used by

  • Peer-to-peer education
  • Relational Spaces
How it works6 steps

  1. Inbox folderDrop items mid-work, a scan files them

  2. Tools folderSpecs, templates, atmospheres, design system, workflows

  3. Cut configs and templatesConfigs select content; templates shape layout

  4. Activity folderOne file per change to the system

  5. Outbox folderRendered frames and public deliverables

  6. Getting Started.htmlThe self-contained entry point

Settled5

  • Packet stays pristineShippable, and cuts never go inside it

  • InstallOpen Getting Started.html and copy the adapter prompt

  • Nothing is deletedSuperseded files move to a deprecated folder

  • Build manifestDetects drift when bundled HTML is edited in place

  • Activity entriesCarry the four design principles

Shareable pages

Tag the notes you want to share and say who the page is for. You get back one web page that opens anywhere, and your notes stay where they are.

Used by

  • Peer-to-peer education
How it works6 steps

  1. TagVault files get a content-tag in their visibility array

  2. Cut configNames tag, audience, lens, output, window

  3. Body sectionsOverride the contact overlay, then template defaults

  4. Contact overlayThe contact’s rendering preferences layer over style tokens

  5. FrameRenders one self-contained HTML packet

  6. Voice passRuns after render, before structural checks

Settled5

  • Tag is a pointerFiles are never copied, tags never stripped

  • Cut and lensA cut is author-routed; a lens is queried from a tagged pool

  • Output is canonicalA mirror is byte-identical and written by the build

  • Audio playerOn unless the cut turns it off

  • Feedback logAppend-only; re-cuts respect applied entries

Still open3

  • Cross-vault pool resolutionSpecified; the build is not stated

  • Lens candidatesWait for promotion at three or more instances

Dual-Ledger Authentication

A member proves participation by showing a private record overlaps the community’s anonymized broadcast. No login, no issuer.

Used by

  • Super Connector bounty
  • Matchmaking events
How it works6 steps

  1. Individual ledgerAppend-only, on the device, never syncs

  2. Each entryCarries time, design principles, visibility

  3. Community broadcastAnonymized shape of activity, regular cadence

  4. Chosen sliceThe participant brings part of their ledger

  5. OverlapIn time and principle, supports the claim

  6. ComparisonRuns on the participant’s device; an optional timeline anchor

Settled4

  • Two independent recordsResist forgery; time is required

  • Bound to a historyThe claim binds to a history, not a name

  • SufficiencySet by the verifier, case by case

  • The anchorA notary, not the authentication mechanism

AlsoConstellation, Refuses

Constellation

The accumulated pattern of a participant’s activity over time. The quantity a claim is checked against.

Refuses

Login, identity provider, issuer, legal identity, shipping the ledger to anyone, disclosure beyond the minimum.

Local Assembly

Each party interprets its own material and answers questions from other parties’ agents. No central interpreter.

How it works6 steps

  1. EdgeHolds a vault plus an agent

  2. Visibility firstA manifest hand-off exposes a scoped projection

  3. Pass 1, selfThe edge interprets its own contribution

  4. Pass 2, presenceThe edge notes that others contributed

  5. Pass 3, meaningA cross-edge query to the edge that can interpret

  6. Scoped reportThe answer returns as one; the relational space composes the views

Settled5

  • Meaning resolves where it livesNot in an aggregate

  • No new storeIt reads existing spec files

  • Neither fabricatesThe witness holds the occurrence; the contributor holds the meaning

  • Self pass aloneThe minimum, and runs without federation

  • No reachable agentAssembly stops at presence

Redacted manifest

What moves when you share: an opaque identifier, a timestamp, and the design principle the work stands on. No names, no paths, no content. The work itself never moves, so you cannot leak it by contributing.

How it works5 steps

  1. ScannerReads only the files you tagged for the community

  2. Full manifestStays private, outside the part of the server anyone can ask

  3. Redacted manifestAn opaque number and a last-active date

  4. CompareThe server checks it against the last broadcast and answers only the person who asked

  5. BaselineAfter an answer, the redacted manifest becomes the new baseline

Settled2

  • Shapes, not contentThe work stays on its owner’s machine

  • Two separate actsContributing a shape and granting access to the work

Still open2

  • Full manifestContent or metadata only

  • Commons contributionHow a pair’s manifest becomes one is not specified

Community Legibility MVP

The MVP data flow, drawn as layers. Each person keeps their own network on top. One MCP layer on a shared server does the comparing and filtering. The commons sits underneath and holds shapes only.

How it works9 steps

  1. ScanMegan’s scanner sends records for tagged files to the server

  2. SyncHer live vault syncs to a private copy on the server, outside the MCP zone

  3. AskKyle’s AI asks what changed, sending a token and “I’m Kyle”

  4. Compare and filterThe server compares the two manifests, then narrows the result to Kyle

  5. AnswerThe scoped answer returns to Kyle’s AI over MCP

  6. BaselineThe redacted manifest becomes the new baseline

  7. CutMegan drops a cut in her folder for Kyle

  8. MirrorThe reverse runs through Kyle’s scanner and his cuts folder

  9. CommonsEither person can add a shape to the commons; nothing else leaves

Settled5

  • The contributor decidesContributing a shape and granting access to the work are separate acts

  • Shapes, not contentThe work stays on its owner’s machine or in published cuts on the server

  • Reading takes a second stepMCP, per relationship, through the dual-ledger gate

  • A token on every arrowEvery arrow into the server carries a community token

  • EventsInsights drop in with the name stripped; the contributor’s vault keeps the named receipt

Still open6

  • Full manifestContent or metadata only

  • The serverWhose hardware, whose network, who administers

  • Kyle’s viewWhat he sees beyond the redacted table

  • Kyle’s halfHis setup is undecided

  • Commons contributionHow a pair’s manifest becomes one is not specified

  • StatusThe technical spec says in progress, the validation map says designed

Source: Working notes, topology of 2026-05-28. Nothing here is built yet.

  • Teaching stays openThe Peer Educator prize rewards depth of teaching, not a credential

Program

Super Connector bounty

A public prize for whoever trains and brings in the most people who show up. Claiming it is how the activity ledger gets tested.

Runs on

  • Dual-Ledger Authentication
How it works4 steps

  1. Shares are loggedWhen someone shares over the network at an event, the community keeps that log

  2. Entrants submit their own ledgerFor the events they attended

  3. The two records must matchThe same share at the same time in both logs; that match is the dual ledger

  4. Commons contributions countData earns points when someone else pulls it from the commons

Settled3

  • Turnout is the riskNo people, no events, no signal

  • Depth over reachRepeat attendance is the stronger signal

  • The leaderboard is the marketingThe finalists are the content

Still open2

  • FundingThere is no money for the prize yet

  • The rewardNot set

Source: The grant program walkthrough, 5 July 2026.

Program

Relational Spaces

Sessions where two or more people bring their own data into one shared view, and an AI facilitator finds the connections between their work. Nobody hands over their vault.

Runs on

  • Local Legibility Packet
How it works5 steps

  1. Each personKeeps their own vault

  2. Visibility gateEach person decides what goes into their data file

  3. Shared lensMerges and layers the data files

  4. FacilitatorReads the combined stream and surfaces overlaps and tensions; it stores nothing

  5. Activity dataFlows back to each person as a record of what they contributed

Settled2

  • The surface comes to your dataNot the other way round

  • Design principles are the comparisonThe four principles are the axes work is compared on

Still open1

  • Live sessionsSpecified, not built

Program

Matchmaking events

An evening where people who took the course meet the people they should know. The server ranks who to talk to, and both phones stamp that the meeting happened.

Runs on

  • Dual-Ledger Authentication
How it works4 steps

  1. BeforeEach person arrives with the card they made in the course

  2. EventSign in, ranked list, review, network, scan cards

  3. Working sessionThen a handoff between helpers, and a pour into the commons

  4. Dual ledgerBoth phones stamp the meeting; the community keeps a thin witness

Settled5

  • Ranked listServer-made, replaces a separate placement round

  • Sign-inActivates your contributed insights

  • No extractionInsights pass live; the community records only that two people met

  • The commonsHolds chosen principles, unmapped to any person

  • NetworkingTwenty minutes in the current plan

Still open3

  • Sign-inA scan plus a confirm button, a typed name, or something else

  • Exchange transferUSB or local network; the physical form is undecided

  • PacingBeyond the twenty-minute window is unset

Source: Working notes. A public write-up is not yet available.
