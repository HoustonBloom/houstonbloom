The spec, part by part

What the Community Legibility Spec is made of, and how the parts connect

A small set of separate pieces that let communities recognize each other without a platform in the middle. A line on the map means one part reads from or builds on the other.

5 parts and 8 lines. Each part says whether it is built, published, prototyped or only designed.

Groups

    • Publish. How work leaves a private vault as something a person can read.
    • Prove and share. How a member shows they took part, and how views are composed without a central owner.
    • Connect people. How people and organizations are recorded and brought together.

    The five parts, in depth

    Infrastructure is what programs run on, and each one lists the skills and tools it uses. A program lists the infrastructure it runs on. Open a part to see how it works, what is settled, and what is still open. Status is as of 30 September 2026. Dashed lines in a diagram are specified, not built.

    Cuts and lenses

    Content plus a cut plus a frame makes an intelligence packet. A lens is the second route, queried from a tagged pool.

    Uses

    • /cut-packet
    • /voice
    • /style-package
    • /visual-asset-atlas
    • /artifact-sourcing
    • /display-palette
    • /check-gallery
    • /complete
    How it works6 steps

    1. TagVault files get a content-tag in their visibility array

    2. Cut configNames tag, audience, lens, output, window

    3. Body sectionsOverride the contact overlay, then template defaults

    4. Contact overlayThe contact’s rendering preferences layer over style tokens

    5. FrameRenders one self-contained HTML packet

    6. Voice passRuns after render, before structural checks

    Settled5

    • Tag is a pointerFiles are never copied, tags never stripped

    • Cut and lensA cut is author-routed; a lens is queried from a tagged pool

    • Output is canonicalA mirror is byte-identical and written by the build

    • Audio playerOn unless the cut turns it off

    • Feedback logAppend-only; re-cuts respect applied entries

    Still open3

    • Template chrome limitsStill in trial

    • Cross-vault pool resolutionSpecified; the build is not stated

    • Lens candidatesWait for promotion at three or more instances

    Skills and tools8

    • /cut-packetRenders the frame from a cut config.

    • /voiceRuns the voice pass after render, before structural checks.

    • /style-packageRegisters the styles that sit beneath the template defaults.

    • /visual-asset-atlasPlans visuals for cuts and saves each asset.

    • /artifact-sourcingFinds prior cuts to source from, catalog first.

    • /display-paletteSupplies the display patterns the display pass chooses from.

    • /check-galleryApplies favorite and deprecation marks to cuts.

    • /completeStep 7 renders the session-report cut.

    Local Brain packet

    A vault-agnostic, installable system that turns markdown folders into shareable HTML artifacts.

    Uses

    • /scan
    • /yaml-audit
    How it works6 steps

    1. Inbox folderDrop items mid-work, a scan files them

    2. Tools folderSpecs, templates, atmospheres, design system, workflows

    3. Cut configs and templatesConfigs select content; templates shape layout

    4. Activity folderOne file per change to the system

    5. Outbox folderRendered frames and public deliverables

    6. Getting Started.htmlThe self-contained entry point

    Settled5

    • Packet stays pristineShippable, and cuts never go inside it

    • InstallOpen Getting Started.html and copy the adapter prompt

    • Nothing is deletedSuperseded files move to a deprecated folder

    • Build manifestDetects drift when bundled HTML is edited in place

    • Activity entriesCarry the four design principles

    Skills and tools2

    • /scanFiles the packet inbox, 00_inbox.

    • /yaml-auditNormalizes frontmatter in packet files only.

    Dual-Ledger Authentication

    A member proves participation by showing a private record overlaps the community’s anonymized broadcast. No login, no issuer.

    Uses

    No skills or tools linked yet.

    Used by

    • Compare Connections
    How it works6 steps

    1. Individual ledgerAppend-only, on the device, never syncs

    2. Each entryCarries time, design principles, visibility

    3. Community broadcastAnonymized shape of activity, regular cadence

    4. Chosen sliceThe participant brings part of their ledger

    5. OverlapIn time and principle, supports the claim

    6. ComparisonRuns on the participant’s device; an optional timeline anchor

    Settled4

    • Two independent recordsResist forgery; time is required

    • Bound to a historyThe claim binds to a history, not a name

    • SufficiencySet by the verifier, case by case

    • The anchorA notary, not the authentication mechanism

    AlsoConstellation, Refuses

    Constellation

    The accumulated pattern of a participant’s activity over time. The quantity a claim is checked against. It is the construct the method rests on, not the method’s name.

    Refuses

    Login, identity provider, issuer, legal identity, shipping the ledger to anyone, disclosure beyond the minimum.

    Local Assembly

    Each party interprets its own material and answers questions from other parties’ agents. No central interpreter.

    Uses

    No skills or tools linked yet.

    How it works6 steps

    1. EdgeHolds a vault plus an agent

    2. Visibility firstA manifest hand-off exposes a scoped projection

    3. Pass 1, selfThe edge interprets its own contribution

    4. Pass 2, presenceThe edge notes that others contributed

    5. Pass 3, meaningA cross-edge query to the edge that can interpret

    6. Scoped reportThe answer returns as one; the relational space composes the views

    Settled5

    • Meaning resolves where it livesNot in an aggregate

    • No new storeIt reads existing spec files

    • Neither fabricatesThe witness holds the occurrence; the contributor holds the meaning

    • Self pass aloneThe minimum, and runs without federation

    • No reachable agentAssembly stops at presence
