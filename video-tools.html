How it runs

Getting started

Step 1

Get the local AI

These run on a computer, not a phone. On lmstudio.ai/download choose Bionic, copy the download link, paste it into the browser on the computer you will use, and open the downloaded file to install.

Step 2

Download the tools, point your AI at it

Download the folder from GitHub and put it wherever you keep projects, or give your AI this prompt. Then open Bionic, make a new project, and choose that folder (its docs).

Show the prompt that fetches it
prompt-to-get-the-tools.txt 
Hi. Get me the video tools from Houston Bloom.

1. Ask me where I keep projects before you put anything anywhere. If I have no answer, suggest a sensible place on this computer and wait for a yes.

2. Get https://github.com/HoustonBloom/video-tools into a folder called video-tools inside that place: clone it if git is on this computer, otherwise download https://github.com/HoustonBloom/video-tools/archive/refs/heads/main.zip and unzip it there.

3. Reply with the full path to the folder, so I can point Bionic at it.

If you get stuck, tell me which step and the exact error. Don't guess.

Step 3

Paste this to set up

It asks which computer it is on, installs Python and ffmpeg for that one, and stops with the exact error if anything fails.

Show the set-up prompt
prompt-to-set-up.txt 
Hi. Set me up to run some local video tools on this computer.

1. Say which operating system this is, Mac, Windows or Linux, and use that row in step 3.

2. Check Python 3.12 or later, the version these ran on. Try python --version, then python3 --version, whichever answers. If neither, send me to https://www.python.org/downloads/ and stop.

3. Install ffmpeg and ffprobe if missing.
  Mac: brew install ffmpeg
  Windows: winget install -e --id Gyan.FFmpeg
  Linux: sudo apt install ffmpeg
The Mac and Linux lines have not been run by us; if one fails, send me to https://ffmpeg.org/download.html and stop.

4. Open a NEW terminal and confirm both answer: ffmpeg -version and ffprobe -version. If either says not found, fix my PATH and tell me what you changed.

5. In this folder run pip install -r requirements.txt. The first transcription also downloads a 464MB model, once.

6. Reply with the OS and the three version numbers and nothing else.

If you get stuck at any step, tell me which step and the exact error. Don't guess.

Step 4

Drop the video in the inbox

Make a folder for it inside video-tools/inbox/ and put the video file there, with the caption file if the platform gave you one. No captions? The walkthrough prompt makes them.

Step 5

Run a tool

Paste the first for the walkthrough, the second for the stills.

Show the walkthrough prompt
prompt-for-a-walkthrough.txt 
Hi. Give me a walkthrough of a recording.

1. Read readthrough/README.md first. If you cannot find it, tell me and stop.

2. My video: [paste the path]. Captions: [paste the path to the .vtt, or say none].

3. No captions? pip install -r transcribe/requirements.txt, then run transcribe/scripts/transcribe.py on the video. An hour took twenty minutes on one computer with no GPU.

4. Run readthrough/scripts/run.py with both. It ends in walkthrough.html or exits non-zero.

5. Do the read it asks for: the whole transcript against the checklist in readthrough/SKILL.md, write segments.json, rebuild.

6. Reply with the absolute path to walkthrough.html at the top, then who was featured and what was found. Do not bury the path.

If it fails, tell me which step and the exact error. Don't guess.
Show the stills prompt
prompt-for-the-stills.txt 
Hi. Pull the best frames out of a recording.

1. Read stills/README.md first. If you cannot find it, tell me and stop.

2. My video: [paste the path]. I want [how many] frames[, from MM:SS to MM:SS, or say the whole thing].

3. Run stills/scripts/pick_stills.py with those, then stills/scripts/build_sheet.py on the folder it wrote.

4. Reply with the absolute path to contact-sheet.html at the top, then how many frames it analysed and kept. Do not bury the path.

Nothing here knows who is in a frame. I look at every picture before one goes out.

If it fails, tell me which step and the exact error. Don't guess.
The parts

The tools

Each one runs on its own. Click one for its page on GitHub.

  • TranscribeReadyCaptions for a video that has none. About twenty minutes for an hour of video.
  • ReadthroughReadyOne page after you submit a video: who was up, when, and the cuts to make.
  • ShortsReadyA vertical clip cut from your video, from a plan you approve first.
  • TightenReadyYour video cut down: the ums and the dead space removed, nothing rewritten.
  • StillsReadyFrames taken throughout your video, on a page to pick from.
  • LoudnessReadyAdjusts the volume of whoever is speaking to a set level.
  • CompositionsComing soonLonger pieces built from your clips.
