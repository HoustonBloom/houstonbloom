Infrastructure

Community Legibility MVP

The MVP data flow, drawn as layers. Each person keeps their own network on top. One MCP layer on a shared server does the comparing and filtering. The commons sits underneath and holds shapes only.

Overview

Status
Designed, not built

How it works

Scan
Megan’s scanner sends records for tagged files to the server
Sync
Her live vault syncs to a private copy on the server, outside the MCP zone
Ask
Kyle’s AI asks what changed, sending a token and “I’m Kyle”
Compare and filter
The server compares the two manifests, then narrows the result to Kyle
Answer
The scoped answer returns to Kyle’s AI over MCP
Baseline
The redacted manifest becomes the new baseline
Cut
Megan drops a cut in her folder for Kyle
Mirror
The reverse runs through Kyle’s scanner and his cuts folder
Commons
Either person can add a shape to the commons; nothing else leaves

Settled

The contributor decides
Contributing a shape and granting access to the work are separate acts
Shapes, not content
The work stays on its owner’s machine or in published cuts on the server
Reading takes a second step
MCP, per relationship, through the dual-ledger gate
A token on every arrow
Every arrow into the server carries a community token
Events
Insights drop in with the name stripped; the contributor’s vault keeps the named receipt
